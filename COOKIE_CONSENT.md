# Система согласия cookie в StreamVibe

Этот файл описывает реализованную работу системы cookie-согласия, созданную в проекте `stream-vibe`.

## Общая идея

Система строится вокруг единого `ConsentManager`, который хранит выбор пользователя и управляет поведением:

- `getConsent()` — получает текущие настройки consent
- `setConsent()` — сохраняет настройки и статус
- `hasConsent(type)` — проверяет, разрешена ли категория

Она работает на клиенте и сохраняет выбор в `localStorage`, а также выставляет cookies для серверной логики.

---

## Что хранится

### В localStorage

Ключ: `cookie_consent`

Сохраняется объект:

```json
{
  "essential": true,
  "functional": false,
  "analytics": false,
  "personalization": false,
  "updatedAt": "2026-..."
}
```

Этот объект содержит полные настройки категоризированного согласия.

### В cookie

- `cookie_consent` — статус: `accepted`, `rejected`, `custom`
- `cookie_consent_prefs` — JSON с выбранными категориями:
  - `functional`
  - `analytics`
  - `personalization`

Это позволяет серверной части читать согласие без зависимости от `localStorage`.

## Логика согласия

### 1. До согласия

- Не запускается PostHog
- Не отправляются аналитические события
- Не записываются PageView
- Разрешены только essential cookies (авторизация/сессия)

### 2. Принять все

Разрешается:

- PostHog трекинг
- Запись PageView
- Сохранение watch history
- Синхронизация favorites
- Analytics events для ratings/comments
- Персонализация

### 3. Только необходимые

Разрешается:

- session cookies
- авторизация
- безопасность

Запрещается:

- PostHog
- PageView tracking
- поведенческая аналитика
- персонализация

### 4. Настроенный выбор

Используются только включённые категории пользователя.

## Реализация технически

### `ConsentManager`

Централизует логику:

- `init()` — загружает сохранённые настройки
- `getConsent()` — возвращает текущий объект настроек
- `getStatus()` — возвращает статус `accepted|rejected|custom`
- `hasAnswered()` — проверяет, отвечал ли пользователь
- `hasConsent(type)` — разрешена ли категория
- `setConsent()` — сохраняет произвольные настройки
- `acceptAll()` — принимает все категории
- `rejectNonEssential()` — разрешает только essential

### Хранение

Файлы `lib/consent/consent-storage.ts` отвечают за:

- `persistConsent()` — сохраняет `localStorage` + cookies
- `loadConsentFromStorage()` — загружает настройки из localStorage
- `loadConsentStatus()` — читает cookie `cookie_consent`

### Серверная проверка

Файлы `lib/consent/server.ts` реализуют чтение cookies на сервере:

- `getServerConsent()` — получает статус и prefs из cookies
- `hasServerConsent(type)` — проверяет категорию на сервере
- `canRecordWatchHistory()` — можно ли сохранять историю просмотров
- `canRecordPageView()` — можно ли записывать page view

Это важно, чтобы backend не записывал аналитику без согласия.

### PostHog

Логика находится в `lib/consent/analytics.ts`.

- до согласия `posthog.opt_out_capturing()`
- после согласия `posthog.opt_in_capturing()`
- `captureAnalyticsEvent()` отправляет события только при `analytics=true`

Реализованы события:

- `page_view`
- `movie_view`
- `watch_progress`
- `favorite_added`
- `rating_added`

### Клиентский контекст

`components/providers/ConsentProvider.tsx` содержит провайдер и UI:

- инициализирует `consentManager`
- синхронизирует PostHog
- показывает баннер и модальное окно
- подключает `AnalyticsTracker` и `MediaViewTracker`

### HTML/CSS/JS

Интерфейс реализован без отдельного дизайна, в стиле текущего сайта: адаптивный, с плавным появлением и скрытием.

- `components/consent/CookieConsent.tsx` — баннер + логика
- `components/consent/CookieConsentModal.tsx` — модальное окно
- `components/consent/cookie-consent.css` — fade/slide анимации и переключатели

## Что блокируется и что сохраняется

### Блокируется

- `PostHog` до аналитического согласия
- аналитические события без `analytics=true`
- `pageview` на сервере без `analytics=true`
- `watch history` на сервере без `functional=true` или `personalization=true`
- поведенческие и персонализационные функции без согласия

### Сохраняется всегда

- essential cookies, связанные с авторизацией и сессией
- пользовательские данные favorites / ratings / comments сами по себе сохраняются, но аналитические события для них зависят от согласия

## Итог

Система соответствует GDPR-подходу: согласие всегда явное, категории разделены, а аналитика не запускается без разрешения пользователя.
