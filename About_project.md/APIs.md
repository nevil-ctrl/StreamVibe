# Архитектура API и Сбор Данных

Поскольку StreamVibe построен на **Next.js App Router**, часть логики выполняется через **Server Actions**, а часть — через стандартные **API Routes** (`app/api/...`).

## Основные API-эндпоинты

### 1. `GET /api/tmdb/...` (Сбор контента)
- Платформа интегрирована с внешним API — **TMDB (The Movie Database)**.
- В приложении есть сервисы (`services/tmdb.service.ts`), которые делают запросы к TMDB для получения списков фильмов, сериалов, деталей, актеров и отзывов.
- *Зачем это нужно:* Мы не храним терабайты видео и описаний у себя на сервере. Вся медиа-база подтягивается динамически по API от TMDB.

### 2. `/api/auth/...` (Аутентификация)
- Внутренние роуты, создаваемые библиотекой **NextAuth.js**.
- Обрабатывают логин, регистрацию, сессии, OAuth-провайдеров (Google/GitHub) и выход из аккаунта.
- Данные пользователей (хэши паролей, email) пишутся в нашу БД PostgreSQL (через Prisma Adapter).

### 3. `/api/stripe/webhook` (Платежи)
- Эндпоинт-приемник. Stripe присылает сюда POST-запросы со статусами платежей (например, `checkout.session.completed` или `invoice.payment_failed`).
- Роут проверяет криптографическую подпись, извлекает ID пользователя из метаданных и обновляет его статус подписки в базе данных.

### 4. `/api/uploadthing` (Загрузка файлов)
- Эндпоинт для работы с библиотекой **UploadThing**.
- Здесь задаются правила загрузки (File Router): например, можно загружать только картинки до 4MB. Выдает ссылки на успешно загруженные изображения профиля.

## Сбор данных (Локальная база)
В дополнение к TMDB, мы собираем локальные данные. Например:
- **Отзывы и Оценки (`Review`, `Rating`)**: Хранятся у нас в БД и привязываются к `movieId` или `showId` из TMDB.
- **История просмотров (`WatchHistory`)**: Когда пользователь нажимает "Play Now", Server Action создает запись в нашей БД. Это позволяет отслеживать, на какой секунде остановился просмотр, и выводить секцию "Продолжить просмотр".
- **Списки ("В избранное", "Мой список")**: Также хранятся в нашей базе и ассоциируются с ID пользователя и ID фильма в TMDB.

Все эти внутренние данные обрабатываются через **Server Actions** (функции с директивой `'use server'`), которые напрямую вызывают Prisma ORM, минуя создание традиционных REST API роутов для каждой мелкой задачи. Это ускоряет разработку и повышает безопасность.
